## PDF 中四组性能数字的原始范围

### Mem0：90% token 与 91% 延迟

[Mem0 论文表 2](https://arxiv.org/pdf/2504.19413)在 **LoCoMo 长对话问答**上，将每次把完整对话交给模型的 full-context 基线，与检索后只注入相关记忆的 Mem0 比较。表中“memory tokens”分别为 **26,031** 与 **1,764**，约减少 **93.2%**；回答的**总 p95 延迟**分别为 **17.117 秒**与 **1.440 秒**，约下降 **91.6%**。论文摘要将结果概括为超过 90% 的 token 成本节省及约 91% 的 p95 降幅。

必须同时报告质量权衡：表 2 的完整上下文 LLM-as-a-Judge 分数为 **72.90**，Mem0 为 **66.88**。文中的 token 定义是检索后提供给回答模型的上下文，并非全部记忆抽取、更新、存储、重建和运行维护开销的总账；p95 对比是特定数据、模型和基线下的检索加回答耗时。PDF 表述的“通常 1,800 对 26,000”“所有生产用户首日回本”超出可核实证据。Memoria 应自己测注入 token、构建/维护成本、p50/p95 及回答质量，不能把这些百分比写作项目实测收益。

### Snowflake：20% 准确率与 39% 工具调用

[Snowflake 原文](https://www.snowflake.com/en/blog/agent-context-layer-trustworthy-data-agents/)说的是一个**内部数据 Agent 实验**：查询集需要跨多个 semantic views，给最佳实践基线额外加入明文“数据本体”说明，包括 join keys、表粒度以及 cardinality/fanout 提示。其报告为最终答案准确率 **+20%**、平均工具调用**约 −39%**，另有端到端延迟约 −20%。文章没有给出这里可核验的样本量、绝对准确率基线或“20 个百分点”的口径。PDF 将其泛化为“给记忆系统加一个 ontology 层就提高 20%”并列举通用用户/项目关系，偏离了原实验任务。

## 其余需要修正的表述

- **层数与流向：**CoALA 的记忆模块是工作层加三类长期记忆；“遗忘引擎”是本 PDF 的设计建议。经历、事实和技能不应自动线性升层。工作记忆包含活动状态与目标，不只是当前上下文窗口的字符串。
- **保留期与容量：**PDF 的情景 30/90 天、SQLite 少于一万条事实、技能“每周复现且成功三次”、每日定时清理等是示例阈值，八个原始来源并未证明这些值适用于 Memoria。优先以来源类型、是否置顶、审计要求和本地评测决定。
- **共享边界：**物理上共用 SQLite 不代表可以共享读取。Agent key、空间授权、待审状态和版本条件必须在查询及写入时执行。Anthropic API Memory Tool 的底层存储和隔离由使用者实现；Letta 当前云共享仓库也不能直接推导 Memoria 的权限语义。
- **遗忘含义：**不再召回、软归档、事实替代、撤销权限和真正删除并不相同。Graphiti 保留被失效事实的来源和历史供追溯；Memoria 对来源删除的级联以及隐私删除应有独立规则。
- **未经核实的营销句：**PDF 的“所有生产用户首日回本”“长任务失败主要因为上下文丢失”“热/温/冷对应固定毫秒数”等不能作为已验证结论；2026-10-09 的这组一手来源不足以支持它们的普遍性。

设计与评测以[分层说明](README.md)和仓库实际代码为准。本文列出的外部收益仅是各来源自己的实验或产品机制，不能代替 Memoria-Agent 的基线与回归结果。
