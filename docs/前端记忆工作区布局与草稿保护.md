# 前端记忆工作区布局与草稿保护（2026-09-28）

## 操作路径

记忆页分为「有效记忆库」「待审核候选」「存储与任务」三个明确入口。记忆库给搜索和已生效记忆更多空间，手动添加放在旁侧；待审核候选独立展示；Markdown 文件和后台抽取记录归入存储与任务。入口保留在当前浏览器标签页的 `sessionStorage` 中，切换到其他主页面再返回时仍能看到上次使用的分区。

点击记忆卡片的「检查并纠正」后，原生模态窗口立即出现在视野中央，焦点落在内容输入框。窗口先显示当前有效内容，再提供修改表单、来源 ID 和版本时间线；按 Esc、关闭按钮或点击遮罩可退出。保存纠正后，窗口内显示成功消息，并继续展示更新后的版本链。窄屏时窗口限制在视口内，内部独立滚动。

## Markdown 文件与草稿

「存储与任务」明确说明 SQLite 是有效记忆和审核状态的可靠来源：`MEMORY.md` 是只读生成视图，`SELF.md` 可编辑并注入对话，`PENDING.md` 仅保留旧版记录。每个文件都有用途说明、保存状态和独立操作入口。

编辑 `SELF.md` 或 `PENDING.md` 时，未保存内容暂存于当前浏览器标签页的 `sessionStorage`，切换文件或主页面后可恢复；文件保存成功后删除对应草稿。界面会标示「草稿未保存」，避免把浏览器草稿误认为已经写入本地文件。切换文件的读取请求有卸载保护，旧请求不会覆盖当前文件；父组件刷新也不会重新读取并抹掉输入。

## 验证点

浏览器回归覆盖：检查窗口立即出现且编辑框获得焦点；桌面和窄屏不产生横向溢出；纠正后窗口内可见新版时间线；记忆页分区切换；Markdown 草稿跨分区和主页面保留、保存后清除。前端构建检查 TypeScript 类型与资源打包。
