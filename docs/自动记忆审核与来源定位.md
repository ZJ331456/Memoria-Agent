# 自动记忆审核与来源定位（2026-09-28）

[文档导航](README.md) · [个人记忆模块](../memoria/memory/README.md) · [API 接口](API接口文档.md)

## 用户流程

对话结束后，后台任务仍负责调用模型提取候选，但不会直接写入有效记忆。用户在 Dashboard「记忆 → 待审核候选」中查看候选，可先点「查看原始对话」，修改正文、类型或重要度，再批准写入或拒绝。已批准记忆的检查窗口、历史版本和后台任务中的来源 ID 也可跳回对应的原始用户消息。

来源跳转先通过 `GET /api/messages/{message_id}/source` 得到会话 ID，再请求 `GET /api/sessions/{session_id}/messages?anchor_id={message_id}`。后一接口读取原文附近的消息并在聊天页高亮，能够定位超出默认最近 100 条范围的旧消息。

## 数据和状态

- `memory_reviews` 按 `(job_id, ordinal)` 唯一保存候选，状态为 `pending → applying → approved` 或 `pending → rejected`。记录候选内容、类型、重要度、来源消息 ID、写入后记忆 ID 和实际动作。
- worker 只负责提取和幂等入队；任务 `completed` 表示提取完成，不代表候选自动生效。旧数据库里已经生效的历史自动记忆保持原状态。
- 批准接口先原子领取待审核项，再调用现有 `MemoryEngine.remember` 完成去重、强化或替代。明确批准的候选可以替代此前由用户纠正的版本；重复写入会记录为 `skipped`。失败恢复为 `pending`；重启时未完成的 `applying` 也恢复待审核。原有来源操作账本防止重试重复强化。
- 只有已批准后形成的 `active` 记忆才参与检索与 `MEMORY.md` 投影；拒绝的候选不会写入记忆表。手动新增记忆和 Agent 工具的显式写入保持原有行为。
- 原始消息或整个会话被删除后，来源跳转返回 404；保留下来的记忆及审核记录不会伪造缺失的原文。

## API 与兼容边界

`GET /api/memory-reviews` 默认返回最多 100 条待审核项，可按状态查询历史；`POST /api/memory-reviews/{id}/approve` 接收审核后的内容、类型和重要度；`POST /api/memory-reviews/{id}/reject` 拒绝候选。重复处理返回 409，字段校验失败返回 422。

审核队列的可靠来源是 SQLite。`PENDING.md` 保留为旧版可读层，新提取候选不会再追加到该文件。当前按单用户本地服务设计；队列列表尚未提供跨页浏览，超过默认页大小时需处理已显示的候选后继续读取。

此队列服务个人聊天；共享记忆另用 `proposals`、空间角色和 `X-Agent-Key`，详见[共享记忆治理](记忆治理与多Agent共享记忆.md)。个人手动添加与 `memorize` 工具直接写入，不经过自动候选队列。

## 验证

后端回归覆盖候选入队幂等、拒绝后不生效、批准后按修订内容生效、重复决定冲突、重启恢复 `applying`、旧消息的锚点读取和错误会话拒绝。浏览器回归覆盖审核表单、批准后移出队列，以及来源消息高亮跳转。

从仓库根目录运行 `python -m pytest -q tests/test_memory_review.py`；浏览器模拟测试与范围见[前端 E2E](../frontend/e2e/README.md)。
