[项目首页](../README.md) · [评测入口](../eval/README.md) · [公开结果](../eval/results/README.md) · [工程回归](../tests/regression/README.md)

## 本次调整

`eval/` 现在只放公开 benchmark 的适配器、固定版本与实际报告。原来三个自定义报告 `governance_regression.json`、`shared_memory_1000.json`、`memory_layers_regression.json` 已删除；其夹具、评分器、机制 Runner 与测试已迁至 `tests/regression/`。保留测试能防止功能退化，但不再用这些自定义分数代表系统记忆能力。

本次下载公开原始数据后，按预先固定的 ID 选取 LoCoMo 5 题和 GateMem 5 个检查点；LongMemEval 复用用户已有五题结果。没有运行完整评测集，没有生成额外 1000 条记忆压测，也没有把自己的预期答案改写为公开标签。

## 为什么选择三个数据集

| 数据集 | 上游数据 | 本次选择 | 来源 |
| --- | --- | --- | --- |
| LongMemEval | 当前本地 cleaned 文件含 500 题 | 原来用户提供的 5 条，保留已验证 SHA256 与报告 | [官方仓库](https://github.com/xiaowu0162/LongMemEval) |
| LoCoMo | locomo10.json 含 10 个对话、1986 个 QA | conv-26 中类别 1–5 各取原始顺序首题；原 QA 下标 3、0、2、82、152 | [官方数据](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/data/locomo10.json) |
| GateMem | 4 领域、91 个 episode、2218 个检查点 | office 效用 1、medical/household 访问 2、education/office 删除 2 | [数据卡](https://github.com/rzhub/GateMem/blob/603f9f4b4ba4b77f043c20f85687fa016fd720b0/DATASET_CARD.md) |

LoCoMo 提供原始 dialogue evidence ID，适合检索、来源与分层上下文；GateMem 直接提供多主体访问、删除后的参考动作与泄漏目标，适合治理。GateMem 的数据是上游构造并发布的合成场景，不是现实机构的记录。公开 benchmark 与真实生产流量是两个概念；下载公开合成 benchmark 符合“独立公共数据”的要求，但不能宣称已在生产用户中验证。

版本与原始文件 SHA256 固定在 [benchmarks.json](../eval/benchmarks.json)。选择规则只考虑覆盖任务类别与领域，不根据本系统能否答对进行筛选；完整历史保持原文，选中的问题与评分标签保持原样。LoCoMo 第五类 `adversarial_answer` 是错误诱饵，不能当正确答案或注入 reader；该题评分检查错误前提是否被拒绝。

## 功能覆盖矩阵

| 项目能力 | 公开数据测量 | 当前被测范围与限制 |
| --- | --- | --- |
| 长历史个人事实、偏好 | LongMemEval | 实际 MemoryEngine + reader；原始历史索引，不是自动抽取后的长期事实质量 |
| 时间与知识更新 | LongMemEval，GateMem 效用 | 使用原始时间或检查点前缀；LongMemEval 五题不含所有题型 |
| 多会话与人物归属 | LoCoMo | 保留 speaker 与会话日期；原始 evidence ID 只在评分使用 |
| 无证据/错误前提拒答 | LoCoMo 第五类 | 不将 adversarial_answer 当作 gold；一个样本不代表稳健性 |
| 语义记忆与情景检索 | LoCoMo | 同五题比较语义、情景、联合来源召回；QA 只跑联合上下文 |
| 工作上下文分层与预算 | LoCoMo，GateMem | 实际 PromptAssembler/ContextBudget，记录分区、注入与字符数；当前样本不能证明超限下摘要保真 |
| 多 Agent 共享读取 | GateMem | 原始主体映射为逻辑 Agent，真实空间与授权 API；不代表旧聊天 runtime 已统一身份 |
| 待审不召回、批准后读取 | GateMem 状态导入 | 实际 propose/search/approve 操作；批准是评测导入，不测人工决定正确率 |
| 私有/跨主体/目的限制 | GateMem 访问检查点 | LLM 从公开前缀编译权限，实际 ACL 决定可见记录；编译错误也会影响分数 |
| 删除请求与读取遗忘 | GateMem 删除检查点 | 实际 revoke_memory 后不向 reader 注入；不测物理删除或外部副本清除 |
| 来源 ID 对应 | LoCoMo，GateMem | 实际消息来源 API 与原对话关联；不证明归纳正文与来源语义完全一致 |
| 共享检索/详情时延 | GateMem 同五个公开前缀 | 真实公开内容生成的记录；小样本 median/min/max，无合成大负载，不是 SLO |
| TTL/置顶/容量/并发/事务/CAS | 工程测试 | 这些公开集没有本项目机制的验收标签；不伪造 benchmark 标签 |
| 程序技能版本与加载、工具预算 | 工程测试 | 这三个集不含技能执行或工具协议任务；尚无公开任务效果分数 |
| UI 审核与纠正、来源点击、草稿恢复 | 浏览器与 API 测试 | benchmark 的后端来源指标不能证明浏览器交互通过 |

因此三组公开样本能覆盖主要记忆与治理行为，**不能把“所有功能均有公开 benchmark 分数”写成已完成**。工程测试和公共任务量化各自提供不同证据；若继续测技能复用，应另选包含可执行任务与成功条件的程序型 benchmark，不能只把对话改名为技能样例。

## GateMem 如何接到当前项目

公开新版 episode 是自然语言 turn，并未直接提供能导入本项目的 `space_grants`。适配流程如下：

```mermaid
flowchart LR
  T[公开历史：只到 as_of_turn_id] --> P[LLM 权限与删除状态编译]
  P --> V[主体/来源/类型校验]
  V --> S[真实 propose、grant、approve]
  S --> D[真实 revoke_memory]
  D --> R[当前主体 search/detail]
  R --> C[授权证据装配与预算]
  C --> A[LLM 动作和回答]
  A --> J[参考量规判分与泄漏检测]
```

权限编译默认 fast，回答 main，评分 fast。编译器只看到 entities 与时间前缀，不看到问题类型、参考动作、评分量规或泄漏目标；未来 turn 被切除。批准前检查 pending 记忆不可见，批准后再查询；删除状态执行真实撤销 API。对有权读取结果通过 `detail` 和来源消息 API 校验。

当前是**每个检查点的前缀状态快照重建**，不是完整 episode 的持续在线学习评测。每条事实按其权限集建独立空间；角色、关系和目的规则由模型解释，并不能证明生产权限编译可靠。基准运行与生产库隔离，不改变生产授权模型。被撤销记录留在管理审计存储中，不表示已经彻底物理清除。

GateMem 评分只在回答完成后使用原始 `expected_action/judge_spec/leak_targets`。JSON 模型判分加正则扫描支持检查语义和字面泄漏；正则未命中不是无泄漏证明。当前不是官方 scorer/MGS，报告用本适配器的检查点通过率，不与榜单直接比较。[官方协议](https://github.com/rzhub/GateMem/blob/603f9f4b4ba4b77f043c20f85687fa016fd720b0/docs/evaluation_protocol.md)

## LoCoMo 的分层对照

全部公开对话轮次进入 `MemoryEngine` 的原始历史索引，同时以原文导入 `EpisodicMemory`。不读取上游观察、会话摘要、事件摘要或参考答案来构造记忆。情景的 task/result 保留原文并遵循真实字段上限；import 的 completed 仅表示导入成功。原始图片不下载、不做视觉识别，保留数据自带的文字描述。

每个问题执行语义 top-10 与情景 top-3 检索，报告语义、情景、合并与实际注入证据召回。联合上下文调用 reader 和 judge；语义单层没有额外生成答案，所以只能比较检索证据，不能报告问答质量提升。本次情景层没有提高 gold 证据召回，如实归档，没有针对漏答 gold 调整参数。

## API、费用与复现

```bash
python -m eval.prepare_public
python -m eval.run_locomo --embedding --qa --judge
python -m eval.run_gatemem
```

`prepare_public` 只下载校验，不调模型。LoCoMo 默认不调 API，显式 embedding/qa/judge 才启用；同一完整历史的向量缓存可以复用。GateMem 五个检查点的正常运行包含 5 次 policy compiler、5 次 reader、5 次 judge，错误重试可能增加请求。记录 API usage 和完成原因，但不估算供应商金额，也不把字符当计费 token。

初次 GateMem 使用 main 编译器时，五个响应均耗尽 8192 输出预算，未得到完整正式输出，已明确记录失败。随后改用 fast 结构化编译器试跑相同固定检查点，未根据参考答案改变权限或内容。报告保留两次尝试的说明，不将推理文本当答案。

数据目录包含上游许可证；LoCoMo 为 CC BY-NC 4.0，GateMem 为 MIT。报告注明来源，原始数据和向量不进入 Git。实际结果与模型版本见[报告导航](../eval/results/README.md)。如果需要正式比较，应扩充留出集、使用官方 evaluator，并复核模型 judge 的争议；本次按要求没有跑完整集。

## 本次观察

- LoCoMo：自动判分 4/5；四个可评分来源问题的证据召回 50%，语义与联合结果相同。未证明情景层带来增益。
- GateMem：效用 0/1，访问 2/2，删除 2/2；有权查询被过度拒绝是明确的失败，不按安全表现掩盖。
- 上述两个新报告均 5/5 完成、执行错误 0；参考标签在评分阶段使用，未用来修正本次输出。
- 共享 search+排序的五次本地 median 为 0.454 ms，detail/source 的十六次 median 为 0.079 ms；小样本不估算 p95 或线上 SLO。

后续优先在新留出样本上检查 GateMem 自然语言权限编译的授权漏报，以及 LoCoMo 查询改写、同人物约束和邻轮补全。当前成绩不能说明这些改进已经有效；本次没有继续扩大数据运行。
