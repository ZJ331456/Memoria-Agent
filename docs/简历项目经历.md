# Memoria-Agent 简历项目经历

以下是基于当前代码的技术表述示例。项目时间、个人负责范围和实际测量结果应按自己的经历填写；架构边界见[系统架构](./系统架构与实现说明.md)，评估方法见[评估说明](../eval/README.md)。

```latex
\section{项目经历}
\ResumeItem{Memoria-Agent：可审核记忆与多 Agent 共享治理系统}
[\href{https://github.com/ZJ331456/Memoria-Agent}{\textnormal{项目链接}}]
[项目时间按实际填写]
\textbf{项目描述：}
基于 FastAPI、SQLite、React 和 TypeScript 实现本地 Agent 与独立的共享记忆治理服务，
支持个人记忆审核纠正、来源追溯和按 Agent 身份授权的团队知识共享。

\textbf{核心功能：}
\begin{enumerate}
  \item 构建支持 SSE 流式响应、Tool Calling、会话压缩与取消的 Agent Runtime，
  通过生命周期 Pipeline、Turn Trace 和 Prometheus 指标观察对话执行过程。

  \item 设计长期记忆引擎，融合关键词与可选向量召回；后台任务仅提取候选，
  用户审核后才写入有效记忆，并支持来源消息定位、版本化纠正及来源级撤销。

  \item 实现独立的 Memory Governance 服务：Agent key、私有/共享空间、角色授权、
  提案审核、同主题版本 CAS、有效期、撤销和追加式事件记录；对共享 API 执行空间 ACL。

  \item 使用 Tool Registry、Tool Search、轻量 Skills 和 MCP 客户端扩展工具能力，
  为治理层建立无模型依赖的合成回归集及独立本地性能脚本。
\end{enumerate}
```

**表述边界：**共享空间隔离只适用于 `MemoryGovernance` 和 `/api/shared/*`；旧聊天 runtime 尚未接入 Agent 身份与共享空间。24 条治理案例属于仓库自建合成回归，不是 GateMem、LongMemEval 或 LoCoMo 的官方成绩。主动信息推送和 Telegram 等外部通道尚未实现。
